# Plus v1

Локальное macOS-приложение для совместной работы с Codex. **Один чат — одна директория проекта.** Владелец работает в Tauri, коллега подключается к тому же чату через браузер.

## Что уже работает

- Создание проекта с выбором папки через нативный диалог.
- Общий чат с авторством сообщений, сохранением истории и WebSocket-синхронизацией.
- Отдельные режимы отправки: «Команда» и «Агент». Обычная переписка не запускает Codex.
- Одноразовые приглашения на 24 часа, гостевые сессии одного проекта, отзыв доступа.
- PNG/JPEG/WebP до 6 МБ, до четырёх изображений в сообщении; изображения передаются агенту.
- Скриншоты агента из папки проекта и временных папок Mac сохраняются во вложения и отображаются в истории, в том числе у коллег.
- Реальный Codex App Server: поток ответов, текущая команда/инструмент, очередь задач, остановка, продолжение сессии, выбор модели.
- По умолчанию — чтение. Владелец может разрешить изменение файлов и подтвердить запросы расширенных разрешений.
- Просмотр состояния Git, изменённых файлов и staged/unstaged diff.
- Настройка публичного адреса существующего Tailscale Funnel.
- В собранную `.app` включены Node.js и закреплённый Codex CLI. Глобальный CLI не обновляется.

## Запуск macOS-приложения

Собранное приложение находится в:

```text
src-tauri/target/release/bundle/macos/Plus.app
```

Откройте его в Finder. Вход владельца выполняется автоматически через нативный IPC. Авторизация Codex используется из локального окружения владельца; при отсутствии входа сначала авторизуйтесь в Codex CLI. Git и инструменты сборки проекта должны быть установлены на Mac.

Сборка предназначена для локального запуска: она подписана ad hoc, без Developer ID и notarization. Дистрибуцию другим владельцам Mac нужно подготовить отдельно.

## Разработка

Нужны Node.js 22.13+ и Rust stable, а также Xcode Command Line Tools. Локально установленный для этой версии Rust находится в `.toolchains/`; скрипт Tauri автоматически использует его, если он существует.

```bash
cd /Users/maksimermolaev/work/main/plus/v1
npm ci
npm run tauri:dev
```

Запуск без desktop-оболочки:

```bash
npm run dev
```

Откройте `http://127.0.0.1:1420`. Для входа владельца в браузере используйте содержимое `.data/owner.key` в форме входа. Этот ключ не предназначен для коллег; для них создаются отдельные приглашения. Секрет не включается в клиентский bundle и не возвращается публичным API.

```bash
npm run typecheck
npm test
npm run tauri:build
```

## Tailscale

После запуска **собранного приложения** сервер доступен на `127.0.0.1:4317`. Для внешнего доступа настройте Funnel:

```bash
tailscale funnel --bg 4317
tailscale funnel status
```

Скопируйте фактический HTTPS-адрес из `status` в настройки Plus → «Адрес для совместной работы». После этого создайте приглашение в проект и отправьте его коллеге. Приложение не включает Funnel автоматически и не меняет существующие настройки Tailscale. Не публикуйте Vite development server; собранный backend сам раздаёт готовый веб-интерфейс.

Приватный вариант для участников вашей Tailscale-сети: `tailscale serve --bg 4317` вместо Funnel.

## Хранение и процессы

- Desktop-данные: `~/Library/Application Support/com.plus.workspace.v1/`.
- Данные `npm run dev`: `.data/`.
- `plus.sqlite`: чаты, сообщения, участники, хеши гостевых токенов и задачи.
- `attachments/`: изображения. `owner.key`: локальный ключ владельца с правами `0600`.
- `server.log`: журнал запуска desktop-backend. Содержимое чатов и заголовки авторизации в него не пишутся.
- `PLUS_DATA_DIR`, `PLUS_PORT`, `PLUS_STATIC_DIR`, `CODEX_BIN` позволяют переопределить окружение.

Один Node backend обслуживает все проекты. Codex запускается отдельным процессом на время задачи, а его сохранённая сессия возобновляется при следующем поручении. На один проект выполняется одна задача. После перезапуска активные задачи помечаются прерванными, очередь отменяется: автоматического повтора действий нет.

## Границы первой версии

- В v1 работа идёт прямо в выбранной директории. Автоматические worktree, commit/push/PR и применение изменений отдельной кнопкой пока не реализованы.
- Это приложение для доверенных коллег. Права HTTP API и approvals контролируются сервером; sandbox Codex ограничивает запись, но режим «Только чтение» не является гарантией ограничения чтения исключительно папкой проекта. Полная изоляция от приватных файлов владельца требует отдельного слоя исполнения.
- Закрытие приложения завершает backend и его процессы Codex. Постоянный фоновый сервис и login item пока не реализованы. Недоступный Mac означает недоступный чат.
- Запросы Codex на выполнение команд/изменение файлов показываются владельцу. Прочие интерактивные методы пока отклоняются, агенту предлагается задать вопрос обычным сообщением.
- Figma и другие MCP-интеграции используют конфигурацию локального Codex. Отдельного интерфейса настройки и авторизации интеграций пока нет.
- Вложения пока только изображения; голос, аудио, отправка агентом произвольных файлов и интерактивный симулятор-preview — следующие этапы.
- История загружается целиком; пагинация и очистка старых вложений пока не реализованы.

## Устройство репозитория

```text
src/           React-интерфейс desktop и браузера
server/        Fastify, SQLite, доступы, очередь, Codex
shared/        TypeScript-модели протокола
src-tauri/     Нативное окно, выбор папки, запуск backend
scripts/       Разработка и упаковка Node/Codex
docs/          Архитектура и визуальный ориентир
```

Ориентир интерфейса и структуры: [CodexMonitor](https://github.com/Dimillian/CodexMonitor), изученный commit `dd61b9a`. Plus реализован отдельно, без зависимости от исходного приложения.
